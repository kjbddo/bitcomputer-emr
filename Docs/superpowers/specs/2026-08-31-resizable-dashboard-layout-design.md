# 대시보드 레이아웃 사용자 조절 설계

**목표:** 대시보드 세 탭의 열 너비와 패널 높이를 사용자가 끌어서 조절하고, 그 배치가 다음 방문에도 남게 한다.

**왜:** 현재 치수가 전부 하드코딩(`300px 1fr 350px`)이고 브레이크포인트마다 다시 하드코딩돼 있다. 어떤 영역은 좁고 어떤 영역은 남는데, 어느 비율이 옳은지는 화면을 쓰는 사람이 안다. 개발자가 값을 추측해 고치는 것보다 조절 수단을 주는 편이 정확하다.

---

## 1. 범위

**대상은 대시보드 페이지 하나다.** `apps/web/src/app/(dashboard)/dashboard/`.

저장소 전체에서 `grid-template-columns` 를 쓰는 파일이 10개지만, 나머지는 폼 그리드(`PatientForm`)·테이블 그리드(`admin/users`)·카드 나열(`styleguide`)이라 성격이 다르다. **3열 작업 레이아웃은 이 페이지뿐이고, 어색하다고 지목된 것도 여기다.**

이 페이지는 탭 세 개를 갖고 각각 다른 그리드를 쓴다.

| 탭 | 그리드 | 열 구성 |
|---|---|---|
| 일반 | `.contentGrid` | `300px 1fr 1fr` |
| 진료 | `.contentGridClinic` | `300px 1fr 350px` |
| 진단서 | `.contentGridCertificate` | `280px 1fr 1fr` |

세로로 쌓인 패널:

| 탭 | 열 | 패널 |
|---|---|---|
| 일반 | 왼쪽 | `SpecialNote` + `History` |
| 일반 | 오른쪽 | `WaitingStatus` + `MedicalInfo` |
| 진료 | 왼쪽 | `Calender` + `ClinicTimelineSection` |
| 진료 | 가운데 | `WaitingStatus` + `Disease` + `Diagnosis` |
| 진료 | 오른쪽 | `ViewDataBase` + `AIReport` |
| 진단서 | 가운데 | `CertificateList` + `CertificateBottom` |

진료 탭 가운데 열이 3단으로 가장 빽빽하다.

**위 표에 없는 열은 패널이 하나뿐이라 세로 핸들이 생기지 않는다** — 일반 탭 가운데(`PatientForm`), 진단서 탭 왼쪽(`CertificatePatientSearch`)과 오른쪽(`MedicalCertificate`). 이 열들은 `flex` 를 `grid` 로 바꿀 필요도 없다.

**범위 밖:** 패널을 다른 열로 옮기기, 패널 숨기기/추가, 탭 순서 변경. 자유 배치 대시보드(`react-grid-layout` 류)는 EMR 작업 화면에 과하고 지금 문제를 풀지 않는다.

## 2. 결정 사항

브레인스토밍에서 정한 것들이다.

| 항목 | 결정 | 대안과 이유 |
|---|---|---|
| 조절 범위 | 열 너비 **+** 패널 높이 | 열만으로는 3단 열의 답답함이 안 풀린다 |
| 저장 위치 | 브라우저 `localStorage` | 서버 저장은 Java API·DB 변경이 필요하고, "여러 의사가 각자 배치를 갖는다"가 지금 요구가 아니다 |
| 저장 단위 | **탭별로 따로** | 세 탭의 열 성격이 달라 공유하면 어색하다 |
| 조작 방식 | 경계 **드래그** | 프리셋·숫자 입력은 눈으로 보며 맞출 수 없다. "어색한 비율"을 고치려면 즉시 피드백이 필요하다 |

## 3. 구조

### 3.1 하드코딩된 치수를 CSS 변수로 뺀다

기존 그리드 구조와 컴포넌트는 그대로 두고 값만 변수화한다.

```css
/* 지금 */
.contentGridClinic { grid-template-columns: 300px 1fr 350px; }

/* 바꾼 뒤 */
.contentGridClinic {
  grid-template-columns: var(--col-1, 300px) var(--col-2, 1fr) var(--col-3, 350px);
}
```

폴백값이 곧 기본 배치다. 변수가 없으면 지금과 똑같이 동작한다.

### 3.2 열을 flex 에서 grid 로 바꾼다

현재 `.leftColumn` 등은 `display: flex; flex-direction: column` 이다. 세로 크기를 끌려면 grid 여야 한다.

```css
.leftColumn {
  display: grid;
  grid-template-rows: var(--row-1, auto) var(--row-2, 1fr);
  gap: var(--space-4);
  min-height: 0;
}
```

**flex 로 하지 않는 이유:** `flex-basis` 를 조절해도 `flex-grow`·`gap`·내용 높이가 섞여 "핸들을 20px 끌면 패널이 20px 커진다"가 성립하지 않는다. grid 는 트랙 크기가 곧 값이라 델타가 그대로 반영된다.

`min-height: 0` 은 grid 자식이 내용 크기 아래로 줄어들 수 있게 하는 데 필요하다. 없으면 트랙을 줄여도 패널이 안 줄어든다.

### 3.3 새 파일 셋

| 파일 | 책임 | 의존 |
|---|---|---|
| `utils/layoutStorage.ts` | 저장 키 구성, 직렬화, **유효성 검사**, 기본값 | 없음 (순수 함수) |
| `hooks/useResizableLayout.ts` | 치수 상태, 저장/복원, 델타 적용, 클램프 | `layoutStorage` |
| `components/ResizeHandle.tsx` | 경계 하나. pointer/키보드 입력을 델타로 변환 | 없음 |

**라이브러리를 쓰지 않는다.** `pointerdown` → `setPointerCapture` → `pointermove` 델타 → `pointerup` 이면 충분하다. `react-grid-layout`(~30KB gzip)은 드래그 이동·충돌 해결·자동 재배치를 위한 것이고 그 셋 다 §1 의 범위 밖이다.

`utils/` 에 두는 것은 이 저장소 관례다 — `llmStatus.ts`, `verificationNotice.ts`, `graphLookupNotice.ts` 가 이미 그 자리에 있다.

## 4. 데이터

### 4.1 저장 형태

탭마다 키 하나.

```
bitcomputer.layout.v1.general
bitcomputer.layout.v1.clinic
bitcomputer.layout.v1.certificate
```

값:

```json
{
  "columns": [300, null, 350],
  "rows": { "left": [220, null], "middle": [180, 260, null] }
}
```

### 4.2 `null` 이 핵심이다

`null` 은 **"남는 공간을 차지한다"(`1fr`)** 를 뜻한다.

모든 트랙에 픽셀을 박으면 창 크기가 바뀔 때 합계가 안 맞아 빈 공간이 남거나 넘친다. 그래서 **각 축마다 최소 하나는 `null` 로 남긴다.** 드래그는 인접한 두 트랙 사이에서만 크기를 주고받고, `1fr` 트랙이 그 결과를 흡수한다.

이 불변식이 깨지면 창 크기 변경 시 레이아웃이 무너진다. 테스트로 고정한다(§6).

### 4.3 버전과 실패 처리

키의 `v1` 은 패널 구성이 바뀔 때를 위한 것이다. 예컨대 진료 가운데 열에 패널이 하나 추가되면 저장된 `rows.middle` 의 길이가 안 맞는다.

**다음 경우 조용히 기본값으로 떨어진다:**

- `JSON.parse` 실패
- 배열 길이가 현재 패널 수와 불일치
- 숫자도 `null` 도 아닌 값
- 최소값 미만 또는 비정상적으로 큰 값
- `localStorage` 접근 자체가 예외(사생활 보호 모드 등)

**레이아웃은 "모르면 기본값"이 안전한 실패다.** 이 저장소의 fail-closed 원칙(`verification`·`llmStatus`·`renalGate`)은 *판정을 정직하게 표시하기* 위한 것이고, 화면 치수는 그 부류가 아니다. 잘못된 배치로 화면을 깨뜨리는 것보다 기본 배치로 되돌리는 편이 낫다. 그 구분을 코드 주석에 남긴다.

## 5. 조작과 경계 조건

### 5.1 최소 크기

| 축 | 최소 |
|---|---|
| 열 | 200px |
| 행 | 120px |

**이유가 미관이 아니다.** 트랙을 0 으로 만들면 그 경계의 핸들도 함께 사라져 되살릴 방법이 없어진다. "기본 배치로" 버튼이 있긴 하지만 다른 조절까지 날아간다.

### 5.2 반응형과의 충돌 — 이 설계에서 가장 까다로운 부분

현재 CSS 는 브레이크포인트마다 열 너비를 다시 정한다(1200px, 1024px, 768px). **인라인 CSS 변수는 미디어쿼리를 이긴다.** 그대로 두면 넓은 화면에서 정한 값이 좁은 화면에도 적용돼 화면이 깨진다.

| 뷰포트 | 동작 |
|---|---|
| > 1024px | 저장값 적용, 핸들 보임 |
| 768~1024px | 저장값 **무시**, 기존 미디어쿼리 유지, 핸들 숨김 |
| ≤ 768px | 1열로 접힘. 저장값 무시, 핸들 숨김 |

구현은 `matchMedia('(min-width: 1025px)')` 로 판단해 변수 자체를 붙이지 않는 것이다. `undefined` 를 넣으면 CSS 폴백값(= 미디어쿼리 결과)이 살아난다.

**저장값을 지우지는 않는다.** 넓은 화면으로 돌아가면 그대로 되살아난다. 좁은 화면에서 한 번 열었다고 설정이 날아가면 안 된다.

### 5.3 되돌리기

각 탭에 "기본 배치로" 버튼 하나. **그 탭 키만** 지운다. 다른 탭 설정은 남는다.

### 5.4 키보드

핸들은 `role="separator"`, `tabIndex=0`, 화살표 키로 10px 단위 이동.

드래그 전용 UI 는 접근성 관점에서 막힌 길이고, 의료 현장에서 마우스만 강제하면 안 된다. `aria-orientation`(`vertical`/`horizontal`)과 설명적인 `aria-label`("왼쪽 열 너비 조절")을 붙인다.

### 5.5 시각적 표시

평소에는 `gap` 안의 얇은 선으로 거의 드러나지 않게, hover/focus 시 강조 + `cursor: col-resize`/`row-resize`. 드래그 중에는 `body` 에 `user-select: none` 을 걸어 텍스트가 선택되지 않게 한다.

기존 디자인 토큰(`--space-*`, 테마 색)을 쓴다. 새 색을 만들지 않는다.

## 6. 테스트

vitest + Testing Library. `pointermove` 는 jsdom 에서 이벤트를 직접 만들어 보낸다.

**`layoutStorage.ts` (DOM 없이):**

- 저장·복원 왕복
- 손상값이 기본값으로 떨어진다 — JSON 파싱 실패, 배열 길이 불일치, 숫자 아닌 값, 범위 밖 값
- `localStorage` 가 예외를 던져도 기본값을 돌려준다

**`useResizableLayout` / `ResizeHandle`:**

- 저장값이 있으면 그 값으로 렌더된다
- 드래그 델타가 인접 두 트랙에 반영된다
- 최소값 아래로 끌어도 최소값에서 멈춘다
- **각 축에 `1fr` 트랙이 최소 하나 남는다** (§4.2 의 불변식)
- 화살표 키로 조절된다
- 1024px 이하에서는 변수가 붙지 않는다

**페이지 단위:**

- "기본 배치로" 가 그 탭 키만 지운다
- 저장 실패가 화면을 죽이지 않는다

**변이로 증명한다:**

| 변이 | 빨개져야 할 테스트 |
|---|---|
| 유효성 검사 제거 | 손상값 폴백 테스트 |
| 최소값 클램프 제거 | 0 드래그 테스트 |
| `1fr` 보장 제거 | 불변식 테스트 |
| 뷰포트 가드 제거 | 1024px 이하 테스트 |

## 7. 위험과 미해결

- **`display: flex` → `grid` 전환이 기존 배치를 미묘하게 바꿀 수 있다.** flex 의 기본 아이템 크기(`flex-shrink: 1`)와 grid 트랙(`auto`)이 항상 같지는 않다. 전환 후 세 탭을 눈으로 확인해야 하고, 그 확인은 테스트가 대신 못 한다
- **`localStorage` 는 브라우저별이다.** 단말을 바꾸면 초기화되고, 같은 단말을 여러 의사가 쓰면 설정이 섞인다. §2 에서 의도적으로 택한 절충이며, 계정별 저장이 필요해지면 `layoutStorage.ts` 의 뒷단만 바꾸면 된다 — 그래서 그 파일을 순수 함수로 분리한다
- **패널 구성이 바뀌면 저장값이 무효가 된다.** `v1` 키와 길이 검사로 조용히 기본값으로 떨어지지만, 사용자 입장에서는 배치가 갑자기 초기화된 것으로 보인다. 패널을 추가·제거할 때 키를 `v2` 로 올릴지 판단이 필요하다
- **다른 세션이 `apps/web` 을 동시에 만지고 있다.** `Diagnosis.tsx` 와 `utils/` 를 건드리는데, 이 작업은 `dashboard/page.tsx`·`page.module.css` 와 새 파일이라 겹침이 적다. 다만 `utils/` 에 파일을 추가하므로 착수 전 확인이 필요하다
