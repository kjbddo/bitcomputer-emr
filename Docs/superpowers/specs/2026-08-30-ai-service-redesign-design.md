# AI 서비스 재구성 설계 — 검색이 고르고 모델이 설명한다

**목표:** LLM 의 역할을 "처방을 고르는 주체"에서 "조회 결과를 설명하는 좁고 검증 가능한 부품"으로 옮긴다.

**전제:** 이 문서의 모든 결정은 2026-08-29~30 실측에 근거한다. 추측이 아니라 관측에서 출발한다.

---

## 1. 무엇을 측정했고 그것이 무엇을 정하는가

세 가지가 설계를 거의 결정한다.

### 1.1 모델은 지어내지 않는다. 중복한다

99 시나리오(§11.3 60 + §11.7 27 + §11.8 12, 마지막 12건은 일부러 유도)에서 후보 밖의 코드는 **0건**이다.

후보를 1건으로 굶기고, 상병과 증상을 어긋내고, 무관한 것만 줘도 밖으로 안 나갔다. 맹장염 증상에 무좀연고·인공눈물만 후보로 줬을 때 모델은 코드를 지어내는 대신 **무좀연고를 두 번 추천했다**(§11.8.2).

**단, 이것은 프롬프트가 금지해서가 아니다.** `prescription_agent.py:119-129` 의 `_sparse_override` 분기는 후보가 부족하면 "실제 제품명·성분명"을 채우라고 **명시적으로 허용한다.** 측정에서 그 분기가 걸리지 않았을 뿐이다. 지어내기가 없다는 관측은 이 분기가 열려 있는 한 조건부다.

### 1.2 후보 품질이 곧 답 품질이다

후보가 수가 코드였을 때는 수가 코드를 추천했다. E11(2형 당뇨) 1순위가 `AA254090 재진진찰료` 였고 `verification.status: passed` 였다.

후보를 약제로 한정하자(PR #9) 같은 모델이 다이아벡스정(메트포르민)·자누메트정·플로가정을 냈다. **모델은 바뀌지 않았다.**

### 1.3 근거 있음 ≠ 옳음

급성 충수염 양상(우하복부 압통·구역·미열)에 상병코드 E11 을 주자, 모델은 조회된 후보 안에서 아세트아미노펜·정장제·항생제를 골랐고 `verification.status = passed` 였다(§11.8.3).

외과적 응급을 놓친 답이지만 모든 코드가 조회 데이터로 추적되므로 근거 검사는 정직하게 통과한다. **검증층은 설계상 추적 가능성만 본다.** 임상 타당성을 보는 것이 없다.

## 2. 따라서: LLM 을 선택자로 두지 않는다

현재 구조는 "모델이 처방을 고르고 순위를 매긴다" 다. `prescription_agent.py` 의 프롬프트가 rank 1·2·3 을 모델에게 요구하고(`:64-71`), `confidence_score` 는 모델 출력 **이후에** 코드로 주입된다(`prescription_api.py:710-719`).

측정은 모델이 고르는 게 아니라 **받은 것을 옮겨 적는다**고 말한다. 그러면 레버리지가 전부 검색·랭킹에 있고, 지금 구조는 그 레버리지를 모델 뒤에 숨긴다.

역할을 다시 나눈다.

| 층 | 하는 일 | 왜 여기인가 |
|---|---|---|
| 검색·랭킹 | 후보 선정과 **순서** | 코호트 co-occurrence + 피드백. 결정론적이고 감사 가능하며 이미 계산된다 |
| 임상 관문 | 금기·위험 신호 차단 | 규칙. 모델이 자기 답을 검사하게 하지 않는다 |
| LLM | 표현 — 왜 이 처방인지, 한국어↔영어 문헌 질의, 요약 | 사전과 규칙이 못 하는 것만 |
| 검증 | 표현이 조회 결과와 어긋나지 않는가 | 이미 있다(B1) |
| 피드백 | 의사 판단을 랭킹에 되먹임 | 이미 배선돼 있고 쓰이지 않는다 |

## 3. 구성 요소

### 3.1 순위는 confidence 가 정한다

**바꾸는 것:** AQL 이 `confidence_score` 내림차순으로 상위 N 을 확정하고, 그 순서를 응답의 rank 로 쓴다. 모델은 순서를 바꾸지 못한다.

`confidence_score` 는 이미 존재한다(`run_prescription_agent.py:233-`):

```
confidence = w_freq·S_freq + w_sim·S_similarity + feedback_adjustment
  S_freq         해당 상병 중 하나라도 포함한 방문들 중 이 처방이 등장한 비율
  S_similarity   해당 상병을 모두 포함한 방문들 중 이 처방이 등장한 비율
  feedback       accepted 가산 / rejected 감산 / missed 소폭 가산 (표본 적을 때 smoothing)
```

**얻는 것 셋:**

- `schema_top3` 의 코드중복이 구조적으로 불가능해진다. 순위가 서로 다른 후보에서 나오므로. §11.5 가 기록한 중복 문제의 근본 해결이다
- 순위에 대한 책임 소재가 명확해진다. "모델이 1순위로 골랐습니다" 가 아니라 **"비슷한 환자 40명 중 23명이 받았습니다"** 라고 말할 수 있다
- 모델 호출이 실패해도 순위는 나온다. 폴백이 빈손이 아니다

**모델에게 남는 일:** 각 항목에 이 환자 맥락에서 왜/왜 아닌지 한 줄. 순위·코드·용량은 조회 결과 그대로.

### 3.2 모델이 "적절한 후보 없음"을 답할 수 있어야 한다

현재 프롬프트는 3건을 채우도록 요구한다. 그래서 후보가 무좀연고뿐일 때 무좀연고를 두 번 쓴다(§11.8.2). **퇴화는 모델의 결함이 아니라 프롬프트가 만든 것이다.**

`_sparse_override`(`:119-129`)의 "부족하면 실제 제품명을 채우라"는 분기를 제거하고, 대신 **거절을 1급 답으로 허용**한다.

- 얻는 것: 퇴화가 사라진다. §1.1 의 조건부 관측이 무조건이 된다
- 얻는 것: "이 상병에 우리 데이터가 뒷받침하는 처방이 없다" 가 유용한 신호가 된다. E78(고지혈증)은 실제로 약 후보가 0건이다(PR #9) — 지금은 그 사실이 `skipped` 로만 표현된다

### 3.3 임상 관문 — 신기능 금기부터

§1.3 의 구멍이다. 검증층은 설계상 못 잡고, LLM 이 자기 답을 검사하게 하는 것도 답이 아니다. 결정론적인 것이 필요하다.

**범위를 신기능 금기로 좁혀 시작한다.** 근거 데이터가 이미 그래프에 있다. `special_notes` 의 `특이사항_norm` 자유텍스트:

```
우측대퇴골자간골절 당뇨 고혈압 치매 신부전 4/5단계 26/1/19 cystatin c 3.29 GFR 13
[6ya / 6.4%['25.08]), DM-CKD, L-spine disc - 3등급
가루약 ... 치매 당뇨 갑상선기능저하증 신우신염 (30년전 투석) L-tube(+)
```

**이것이 가설이 아닌 이유:** PR #9 직후 E11 라이브 추천의 1순위가 **다이아벡스정(메트포르민)** 이다. 메트포르민은 신기능 저하에서 젖산산증 위험으로 금기다. 위 노트의 환자는 **GFR 13** 이다. 지금 이 시스템은 그 환자에게 메트포르민을 1순위로 권하고 `passed` 를 띄운다.

**설계:**

- `special_notes` 에서 신기능 지표를 파싱한다: `GFR <숫자>`, `신부전 <n>단계`, `CKD`, `투석`. 자유텍스트이므로 **못 읽는 경우가 정상**이고, 못 읽었을 때 "금기 없음"으로 읽혀서는 안 된다(GC-3 fail-closed)
- 신배설 약물 목록을 명시적 표로 둔다. 코드 접두가 아니라 성분 기준
- 관문의 출력은 차단이 아니라 **경고**다. B1 과 같은 원칙 — 표시하고 차단하지 않는다. 의사가 최종 판단한다
- 파싱 실패 / 지표 없음 / 약물 목록 밖 → 각각 다른 상태로 구분한다. "확인함·해당없음", "확인 못 함", "경고" 는 셋 다 다르다

**왜 신기능만 먼저인가:** 범위가 좁아 검증 가능하고, 실제 사례가 이미 있고, 오탐 관리가 현실적이다. 레드플래그 증상 규칙(우하복부 압통+발열 → 외과 의뢰)은 자연스러운 다음 단계지만 규칙 저작과 오탐 관리가 별개의 작업이다. 하나를 증명한 뒤 확장한다.

### 3.4 피드백 고리를 실제로 돌린다

`prescription_feedback` 테이블이 있고 confidence AQL 이 이미 소비한다(`accepted_boost` / `rejected_penalty` / `missed_boost` / `feedback_smoothing`). 현재 **3행**이다.

```
prescription_feedback: id, prescription_code, prescription_name, rec_rank,
                       confidence_score, status, reason, history_id, ...
```

닫힌 고리가 이미 배선돼 있으니 만들 것은 없다. **쓰이게 하는 것**이 일이다. 의사가 수용/수정/거절할 때 기록이 남는 경로를 확인하고, 쌓인 뒤 순위가 실제로 움직이는지 본다.

이것이 서사의 핵심이다 — "AI 가 추천했다" 가 아니라 **"우리 병원 의사들이 실제로 이렇게 처방했고, 당신이 거절한 것은 다음부터 덜 나옵니다"**.

## 4. 사용자가 보는 흐름

```
상병 선택
  → 비슷한 환자들이 실제로 받은 처방을 confidence 순으로 제시
      각 항목: 근거 배지("후보 40건 중 23건") + LLM 한 줄 설명
  → 임상 관문에 걸리면 추천 위에 경고 (차단 아님)
  → 뒷받침하는 후보가 없으면 그렇게 말한다 (빈손을 3건으로 채우지 않는다)
  → 의사가 수용/수정/거절 → 다음 순위에 반영
```

LLM 은 여기서 **작고 검증 가능한 역할**만 한다. 그것이 설득력의 원천이다. "LLM 이 진단합니다" 는 방어할 수 없지만, "LLM 이 조회 결과를 읽기 좋게 설명하고, 그 설명이 조회 결과와 어긋나면 화면에 뜹니다" 는 방어된다.

## 5. X-ray

현재 검색 성능이 **다수 라벨 기준선과 같다**(§8.2, EVALUATION.md):

| | |
|---|---:|
| 기준선: 항상 `lung_opacity` 하나만 답하기 | 0.8014 |
| 실측 top-1 any-match | 0.8014 |
| 기준선: 빈도 상위 3개 | 0.9795 |
| 실측 top-3 any-match | 0.9658 |

11개 질환 중 8개가 recall@1 = 0.000 이다. 이 상태로는 "유사 사례를 찾아준다"를 주장할 근거가 없다.

**결정: ROI mask 를 고치고 다시 측정한다.**

임베딩을 mock random projection → DenseNet121 사전학습으로 바꿨을 때 중위권은 올랐지만(`atelectasis` recall@3 0.107→0.467, `pleural_effusion` 0.031→0.453) **1등 자리는 한 라벨도 못 바꿨다**(§8.3). 기존 §3 이 지목한 "mock 임베딩" 진단은 부분적으로만 맞았다.

남은 후보 셋 중 ROI 가 가장 유력하고 가장 검증 가능하다:

- ROI mask 가 지금도 **타원 휴리스틱**이다. 해부학적으로 어긋나면 ROI별 임베딩이 잡음이 된다
- §2 에서 ROI 가중합이 Hit@1 을 +3.4%p 올렸다 — **mock mask 로도 신호가 있다**는 뜻이고, 정합성이 개선되면 더 오를 여지가 있다
- 나머지 둘(ImageNet 도메인 불일치 / reconstruction error 자체의 한계)은 실험 비용이 훨씬 크다

**성공 기준을 미리 못박는다: 다수 라벨 기준선을 넘지 못하면 서사에서 뺀다.** 지표가 올라도 기준선이 함께 오르면 의미가 없다. `EVALUATION.md` §8.5 의 기준선 계산을 모든 측정에 함께 기록한다.

## 6. 무엇으로 증명하는가

발표에서 이 셋이면 충분하다.

| 숫자 | 상태 | 말하는 것 |
|---|---|---|
| 후보 밖 추천률 0/99 | **있다** (§11.3·§11.7·§11.8) | 모델이 데이터를 벗어나지 않는다 |
| 검증 발화율과 근거 | **있다** (§11.8, `schema_top3` 3건 + evidence) | 잘못되면 화면에 뜬다 |
| 신기능 금기 검출률 | 없다 | 임상적으로 위험한 추천을 잡는다 |
| 피드백 전/후 top-1 수용률 | 없다 | **쓸모 있다** |

앞의 둘은 "안전하다"를 말하고, 뒤의 둘만 "쓸모 있다"를 말한다. 지금 프로젝트에 없는 것이 후자다.

`3.1` 의 순위 변경은 이 측정을 쉽게 만든다 — 순위가 결정론적이면 피드백 전후 비교가 모델 변동에 오염되지 않는다.

## 7. 위험과 미해결

- **`special_notes` 파싱은 자유텍스트 상대다.** 형식이 제각각이고(`GFR 13`, `신부전 4/5단계`, `cystatin c 3.29`) 못 읽는 경우가 흔할 것이다. 못 읽었을 때 조용히 통과시키면 §1.3 의 구멍을 다른 모양으로 재현한다. **fail-closed 가 이 부품의 전부다**
- **순위를 confidence 로 옮기면 모델이 임상 맥락으로 순서를 조정할 여지가 사라진다.** 이것은 손실이다. 다만 측정상 모델이 그 조정을 하고 있다는 증거가 없고, 결정론적 순위의 감사 가능성이 더 크다고 판단한다. 반증이 나오면 되돌린다
- **피드백이 쌓이기 전까지 confidence 는 빈도·유사도만 반영한다.** 초기에는 "가장 흔한 처방"에 가깝고, 그게 항상 옳지는 않다
- **레드플래그 증상 규칙은 이번 범위 밖이다.** 맹장염 사례(§1.3)는 신기능 관문으로 닫히지 않는다. 별도 작업으로 남는다
- **발표 문서가 여전히 ReAct 를 주장한다.** `Docs/QnA.md:96`, `Capston-Design-Report.md:132,137,253`, `Script.md:93`, PPT 원고. 코드를 열어보면 어긋난다
